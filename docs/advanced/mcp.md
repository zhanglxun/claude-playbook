# MCP：连接外部世界

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 说清 MCP 是什么，能让 Claude 多做哪些事
- 在终端里添加一个 MCP 服务，并检查是否连上
- 区分三种保存范围，知道配置存在哪里
- 掌握连接外部服务的风险和注意事项

## MCP 是什么

**MCP（Model Context Protocol）可以理解为给 Claude 接上"外接设备"的统一插口。** 默认情况下，Claude Code 能读写你电脑上的文件；接上 MCP 服务后，它还能查日历、读云文档、搜工单、查数据库、操作浏览器。

通俗类比：Claude 是一位能干的助理，MCP 就是你给他开通的各种系统账号。开得越多越方便，但也越要想清楚"开哪些、开多大权限"。

这里的每个外部服务称为一个**MCP 服务器**（server），它可能运行在你的电脑上，也可能是别人托管的在线服务。

## 业务上能做什么

| 业务场景 | 接什么 | 能做的事 |
|---|---|---|
| 会议安排 | 日历 | "查本周我和客户的会议，生成周一行程摘要" |
| 资料汇总 | 云盘、文档 | "读取共享文档里的客户反馈，汇总成表" |
| 项目跟进 | 工单、任务工具 | "列出本周逾期的任务，按负责人归类" |
| 网页核查 | 浏览器 | "打开这几个公司官网，核对公司名称和主营业务" |

具体能连哪些服务，可查 Anthropic 官方的连接器目录和各服务自己的文档。

## 配置步骤（以业务例子演示）

本节在**终端**输入命令。终端是用文字下达命令的窗口：在 VS Code 里点菜单"终端 → 新建终端"即可（见[安装与第一次运行](/advanced/install)）。注意：以 `claude mcp` 开头的命令在**终端**里输入，不是在 Claude 的对话框里。

### 第一步：添加服务

在线服务（最常见）的写法：

```text
claude mcp add --transport http 【自己起的名字】 【服务地址】
```

例如添加官方的 Claude Code 文档服务（无需登录，适合第一次练手）：

```text
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
```

各部分含义：`claude mcp add` 是"添加服务"；`--transport http` 表示服务在网上；名字随便起，之后管理时用；最后是地址。

### 第二步：检查是否连上

```text
claude mcp list
```

状态说明：

| 显示 | 含义 |
|---|---|
| ✔ Connected | 连上了，可以用 |
| ! Needs authentication | 需要登录授权 |
| ✘ Failed to connect | 没连上，检查地址和网络 |

### 第三步：如果需要登录授权

很多办公类服务（如任务、工单、笔记工具）需要你在浏览器里登录并点击"同意"。步骤：

1. 在 Claude Code 对话框输入 `/mcp`。
2. 选中该服务，按回车，选 `Authenticate`。
3. 浏览器自动打开，登录并授权。回到 Claude Code，状态变为已连接。

也可以直接在终端运行 `claude mcp login 【名字】`。

### 第四步：使用

直接用业务语言提要求，必要时点名服务：

```text
请用【服务名】查一下【本周逾期的任务】，按负责人整理成表格，保存到 reports/ 文件夹。
```

第一次调用时 Claude Code 会请你确认，认真看一眼它要做什么再点同意（见[权限与安全](/advanced/permissions)）。

### 管理服务

| 命令 | 作用 |
|---|---|
| `claude mcp list` | 查看全部服务及状态 |
| `claude mcp get 【名字】` | 查看某个服务的详情 |
| `claude mcp remove 【名字】` | 删除（同时清除已保存的登录凭证） |
| `/mcp`（对话框内） | 查看状态、开关服务、重新连接 |

## 三种保存范围

| 范围 | 参数 | 谁能用 | 配置存在哪 |
|---|---|---|---|
| 本地（默认） | 不加 | 只有你，只在当前项目 | 你的用户配置文件 `~/.claude.json` |
| 项目 | `--scope project` | 项目所有成员 | 工作文件夹里的 `.mcp.json` |
| 用户 | `--scope user` | 只有你，所有项目 | `~/.claude.json` |

经验：个人账号类服务用默认或用户范围；需要整个团队统一使用的，才放项目范围，并提交到共享的项目里。**不要把密码或令牌直接写进会被共享的文件。**

## 风险与注意事项

MCP 把 Claude 的能力扩展到了电脑之外，风险也随之扩大：

1. **只连接可信服务。** 官方也提醒：会抓取外部内容的服务，可能让你暴露在"提示词注入"风险下。提示词注入指别人在网页、文档里藏了一段指令，诱使 AI 照做（比如"把所有文件发给某邮箱"）。来路不明的服务不要接，来路不明的文档不要不加甄别地让 AI 处理。
2. **授权范围尽量小。** 登录授权时看清列出的权限，能只读就不要读写；能只开某个项目就不要开整个账号。不再使用的服务及时 `claude mcp remove`。
3. **留意数据外传。** 通过 MCP 发给第三方服务的内容，会离开你的电脑。涉及客户资料、合同、个人信息的内容，先对照公司规定和[使用规范与数据安全](/security/)再决定能不能发。
4. **留意会修改外部数据的操作。** "创建任务、发送消息、改文档"这类动作，要在确认环节看清再同意，不要在批量处理时一路"全部同意"。
5. **项目里的 `.mcp.json` 要先看再批准。** 从别人那里拿到的文件夹，首次打开时 Claude Code 会询问是否批准其中的服务，不确定就先不批准。
6. **服务多了会占"工作记忆"。** 每个服务的工具名称都会占一部分上下文，用不到的及时关闭或删除（见[上下文与用量管理](/advanced/context-usage)）。

## 课堂练习

1. 在终端添加 `claude-code-docs` 服务，用 `claude mcp list` 确认连接。
2. 在 Claude Code 里提问："用 claude-code-docs 服务查一下 `/model` 命令怎么用"，观察回答中标注的服务名。
3. 用 `/mcp` 查看它提供了哪些工具，然后用 `claude mcp remove claude-code-docs` 删掉。
4. 小组讨论：如果你要接入公司的日历和云盘，授权时应该选哪些权限？哪些资料不适合通过它发出去？

## 小结

- MCP 是给 Claude 接外部工具的统一插口。
- 添加三步：`claude mcp add` → `claude mcp list` → 必要时 `/mcp` 授权。
- 守住三条线：只连可信服务、授权范围从小、注意数据外传。
