# 插件与 Mods

> 内容核对日期：2026-10-18；选学内容。部分功能为研究预览/公测，且按套餐和版本开放，请以官方文档为准。

::: tip 选学 · 偏专业
本页偏专业，前半部分（插件的安装与来源判断）人人用得上；后半部分（Mods）面向想深度定制 Claude Code 的人。看不懂 Mods 的代码不影响日常使用，但**安全提醒**部分建议所有人读一遍。
:::

**适合谁**：想安装别人做好的"功能包"，或想给 Claude Code 加界面面板、自定义命令的人。

**学完能**：会安装、停用、卸载插件；会判断一个插件值不值得信任；知道 Mods 是什么、以什么权限运行、如何在安装前先"看一眼它要干什么"。

## 一、插件：把一整套能力打成一个包

在 [Skills](/advanced/skills) 一章里提到过：插件是打包分享技能的方式。更完整地说，**插件（plugin）是一个文件夹，里面可以装技能、子代理、钩子、MCP 服务器等多种组件**，Claude Code 把它们当作一个整体来安装和加载。

插件从**市场（marketplace）**获取。市场不是商店，只是一份"目录清单"，列出有哪些插件、去哪里下载。Claude Code 首次在终端启动交互会话时，会自动添加 Anthropic 的官方市场，其他市场需要你手动添加。

### 常用命令

在会话里输入：

| 目的 | 命令 |
|---|---|
| 打开插件管理面板（含"发现""已安装""市场""错误"几个标签页） | `/plugin` |
| 安装某个插件（会先打开详情页，让你选范围并确认） | `/plugin install 插件名@市场名` |
| 添加一个市场 | `/plugin marketplace add 来源` |
| 立即使新装/更新的插件生效 | `/reload-plugins` |
| 在命令行里列出已装插件 | `claude plugin list` |
| 在命令行里停用/启用/卸载 | `claude plugin disable`、`enable`、`uninstall` |

安装时要选**范围**：只给自己用（用户级）、给这个项目的所有协作者（项目级）、或只给自己在这个项目用（本地级）。装好后，输入 `/` 能看到插件提供的技能，形式是 `/插件名:技能名`。

在桌面应用里，点提示框旁的 **+**，选 **Plugins**；VS Code 里输入 `/plugins`。

装得越多，每次对话背后的"目录信息"越多，会占用上下文和额度。官方市场里的插件在详情页会显示"上下文开销"估算，**用不到的插件建议停用**。

### 怎么判断一个插件能不能信

> 一个插件可以用你的用户权限在你的电脑上执行任意代码。

插件里的钩子、后台监控、MCP 服务器、`bin/` 目录下的可执行文件，都会以**你本人的权限**运行，而且这些程序不受 Claude Code 权限规则和沙箱的约束。所以安装前要像对待"一个陌生人给你的软件"那样检查：

1. **看来源。** 市场名只说明"谁发布了这份目录"，不说明每个插件做了什么。Anthropic 官方市场的名字只有从 Anthropic 官方仓库来的才能使用；同事或公司自建的市场属于"第三方"。
2. **看详情页。** 用 `/plugin` 选中插件，看 **Will install** 一栏列出的命令、技能、钩子、MCP 服务器。
3. **看源码。** 重点看 `hooks/hooks.json`（钩子要跑什么命令）、`.mcp.json`（连接了哪些服务）、`bin/` 目录下的文件。
4. **列清单。** 把仓库下载到本地后，可以用 `claude --plugin-dir 插件目录 plugin details 插件名` 查看它包含的组件清单，这条命令不会启动会话。
5. **留意自动更新。** 开了自动更新的市场，插件会在后台更新，你审查过的文件可能变化。官方市场默认自动更新，其他市场默认不更新。

不再信任某个插件时，用 `claude plugin uninstall 插件名` 卸载；如果连这个市场也不信，直接移除市场（会连带卸载来自它的所有插件）。

企业管理员可以通过托管设置限制可添加的市场、强制安装指定插件，详见 [企业管理](/advanced/optional/admin)。

## 二、Mods：运行在 Claude Code 内部的插件

### 它是什么

**Mod 是一种特殊的插件，它的代码（JavaScript 或 TypeScript 写的"事件处理函数"）直接运行在 Claude Code 内部。** 每当某件事发生——Claude 要调用工具、你提交了提示词、界面某个部分要重画——Claude Code 就会先交给 Mod 的函数处理。Mod 可以：

- **观察**：只是看看，不改变；
- **改写**：改掉事件内容再放行；
- **接管**：自己处理，不让原来的行为发生。

和技能、外部钩子、MCP 相比，Mod 能做到它们做不到的事：

- **在界面里画东西**：侧边面板、提示框上方的横条，带标签页、按钮、输入框；
- **改 Claude Code 自己的界面**：比如加载动画、工具调用那一行的显示；
- **拦截工具调用**：例如 Claude 要执行危险命令时先拦住，弹出提示让你选择放行还是取消；
- **加自定义命令**：一个 `/命令`，立刻运行你写的函数，不需要 Claude 回合。

Mods 在 Claude Code 命令行、桌面应用的 Code 标签页、VS Code 扩展中可用。**Mods 默认开启**，终端需要 Claude Code 2.1.287 及以上，桌面应用需要 2.1.286 及以上（2026 年 10 月 1 日随 2.1.287 正式推出）。

### 内置 Mods

Claude Code 自己的一些功能就是 Mod。在 `/plugin` 的 **Installed** 标签页的 **Built-in** 分组里能看到，不能更新或卸载，但多数可以停用：

| 名称 | 作用 |
|---|---|
| `cc-plugin-agents-md` | 把 `AGENTS.md` 当作项目说明读取 |
| `cc-plugin-diff` | 接管 `/diff` 并绘制变更面板 |
| `cc-plugin-plugin-authoring` | 提供 `plugin-authoring` 技能，帮你让 Claude 写 Mod |
| `cc-plugin-sec-default` | 内置"守卫"，保护组织托管的设置不被用户装的 Mod 篡改；用户不能关闭 |
| `cc-plugin-telemetry` | 发送 Claude Code 自身的分析记录 |
| `cc-plugin-you-should-know` | "你应该知道"提示：旁路助手在提示框上方给出你可能忽略的提醒；默认关闭，需手动开启 |

### 如何获得一个 Mod

- **直接让 Claude 写**：在会话里描述你想要的功能，Claude 会借助 `plugin-authoring` 技能生成一个 Mod。
- **从市场安装**：和普通插件完全一样，`/plugin install 名称@市场名`。
- **试官方示例**：Anthropic 在 `claude-code-playground` 仓库里提供了示例（如在提示框上方显示上下文余量的 `token-weather`、拦截危险命令的 `blast-radius`），是"按现状分享、不提供支持"的样例。

## 三、安全：Mod 以你的权限运行，没有沙箱

这是本页最重要的一节。

> **Mod 以你的权限运行，不受沙箱保护。**

一个 Mod 加载后可以：

- 读写你的用户账号能访问的任何文件，启动程序，发起网络请求；
- 读取你的环境变量和设置文件（可能包含 API 密钥）；
- 看到你发的每一条提示词和 Claude 的每一次工具调用；
- 改写提示词或工具调用，甚至以"你输入的"名义提交提示词；
- 在不问你的情况下批准某些工具调用；
- 调用模型，消耗你的额度。

即使你开启了沙箱，沙箱隔离的是 Claude 运行的命令，**Mod 自己启动的进程不在沙箱内**。Mod 能重新绘制界面的大部分内容，但**不能改写权限确认弹窗**，也就是说，弹窗里显示的内容不会被它篡改。

### 安装前先"看一眼"：`claude plugin validate`

不运行它，就能列出它要做什么。先把插件文件下载到本地（比如克隆仓库），然后在命令行运行：

```text
claude plugin validate ./要检查的mod目录
```

输出里有两行最关键：

- `hooks:`：它会响应哪些事件。如果有 `tool.call` 或 `prompt.submit`，说明它能看到并改你的**每一次工具调用 / 每一条提示词**。
- `calls:`：它会调用哪些能力。重点看这些：

| 调用 | 含义 |
|---|---|
| `$.fs.read`、`$.fs.write` | 读写你能访问的任何文件 |
| `$.process.run`、`$.process.spawn` | 以你的身份启动程序 |
| `$.http.fetch` | 发起网络请求 |
| `$.env.get`、`$.settings.read` | 读取环境变量和设置，可能含密钥 |
| `$.model.complete` | 用你的额度调用模型 |
| `$.prompt.submit` | 代你提交提示词 |

一个简单的判断：**一个"显示用量图表"的 Mod 如果同时要写文件、发网络请求，就要问为什么。**

### 出问题时怎么关

- 停用单个 Mod：`/plugin` 的 **Installed** 标签页停用或卸载其插件；
- 本次会话全部停用：用 `claude --safe-mode` 启动；
- 全部关闭：在 `~/.claude/settings.json` 里设 `"disableAllHooks": true`（注意：这也会让你自己的外部钩子和自定义状态栏停止）。

企业环境中，管理员可以用托管设置禁止用户自装 Mod，详见 [企业管理](/advanced/optional/admin)。

## 动手任务

1. 输入 `/plugin`，进入 **Installed**，找到 **Built-in** 里有哪些内置 Mod。
2. 用 `claude --version` 确认你的版本是否 ≥ 2.1.287。
3. 对任一你信任的插件运行 `claude plugin details 插件名`，看看它的 **Component inventory**（组件清单）里有没有钩子或 MCP 服务器。

## 小结

- 插件 = 一整套能力的安装包；Mod = 运行在 Claude Code 内部、能改界面和拦截动作的插件。
- 两者都以**你的权限**运行，不在沙箱里；先看来源、再看内容，装前用 `claude plugin validate` 看一眼。
- 不确定就不装；装了不用就停用。
