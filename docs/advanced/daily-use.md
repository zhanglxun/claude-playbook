# 日常操作

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 用清晰的方式给 Claude Code 布置任务、中途纠偏
- 在修改落地前后检查它改了什么
- 把文件和对话回退到之前的状态
- 用 Plan 模式让它"先出方案，你确认后再动手"

## 一、怎么布置任务

在输入框里写任务，回车发送。写法和你在网页版里学的提示词原则一致（见 [提示词写法](/basics/prompting)），只是多了"文件"这个维度：

| 要素 | 说明 | 例子 |
|---|---|---|
| 范围 | 哪些文件、哪个子文件夹 | "只看 `访谈记录` 文件夹" |
| 目标 | 要产出什么 | "整理成一张汇总表" |
| 格式 | 文件类型和结构 | "保存为 `汇总.md`，列为：受访者、关注点、原话" |
| 边界 | 不要动什么 | "不要修改原始文件，所有结果放进新建的 `产出` 文件夹" |

```text
请阅读【访谈记录】文件夹中的所有文档，整理成一张汇总表：
- 列：受访者编号、所在部门、最关心的三个问题、一句有代表性的原话
- 保存为【产出/访谈汇总.md】
- 不要修改原始文件
- 完成后告诉我哪些文件信息不全
```

**引用文件**：在输入框里输入 `@` 再打几个字，会弹出文件名供你选择，选中后 Claude 会重点看这个文件。在 VS Code 里，选中编辑区的一段文字后，Claude 自动能看到这段；按 `Option+K`（Mac）或 `Alt+K`（Windows）可以把"文件名加行号"插入到输入框。

**粘贴图片**：截图可以直接粘贴给它看，比如一张图表的截图。

## 二、中途纠偏

Claude 工作时你不必干等：

- **按 `Esc`**（终端里）或点面板里的停止按钮，可以立即打断当前动作，它已经做完的部分会保留，然后你可以补充说明方向
<!-- TODO 核实：VS Code 面板中打断任务的具体按钮和 Esc 是否同样生效，官方 vs-code 页未明确 -->
- 它在工作时你也可以继续打字，消息会排队，等它这一步做完后读取
- 如果它走偏了，直接说"停一下，我要的是……"，比让它做完再推翻省时间

## 三、查看和确认修改

这是日常使用中最重要的习惯：**不要盲目点同意。**

**在 Manual（每步确认）模式下**：Claude 想修改一个文件时，面板会弹出左右对比：左边是原文，右边是拟修改后的内容。你可以：

- 同意（Yes）
- 拒绝（No）
- 直接告诉它换一种做法
- 甚至在对比视图里亲手改几个字再同意，它会知道你改过

需 Claude Code v2.1.275 及以上时，改动较多的文件可以按"每处修改"逐个接受或拒绝（**Accept this change / Reject this change**）；一个文件超过 100 处改动时不提供这个功能，只能整体审阅。

**在 Auto 或 Edit automatically 模式下**：修改会直接落地，不再逐次询问。这时更要在事后检查：

- 看面板里它汇报的"改了什么"
- 在 VS Code 左侧文件列表里打开新建或修改过的文件核对
- 对重要文件，让它"逐条列出你改动了哪里"

::: tip 检查要点
对业务文件，重点核对三件事：数字有没有被改错、引用的来源是否存在、原有内容有没有被误删。
:::

## 四、撤回与回退

Claude Code 会在你每次发出一个任务时，自动给文件拍一个"快照"，这叫**检查点**。出问题时可以回到之前的状态。

### 在 VS Code 面板里

把鼠标移到某条历史消息上，会出现 **回退按钮**，点开后有三个选项：

| 选项 | 效果 |
|---|---|
| Fork conversation from here | 从这条消息开一个新分支对话，已有的文件修改保留 |
| Rewind code to here | 把文件恢复到这条消息之前的样子，对话记录保留 |
| Fork conversation and rewind code | 新开分支对话，同时把文件恢复 |

### 在命令行里

输入 `/rewind`，或在输入框为空时连按两次 `Esc`，打开回退菜单，列出你发过的每条任务。选定后可以：

- 同时恢复代码（文件）和对话
- 只恢复对话
- 只恢复文件
- **从这里开始压缩**（Summarize from here）：把后面的长对话浓缩成摘要，释放空间，不改文件（见 [3.7](/advanced/context-usage)）

回退后，原来那条任务的文字会自动放回输入框，你可以改一改再发。

### 局限，必须知道

- **通过命令行执行的改动无法撤回**：如果 Claude 运行了删除、移动、复制文件的命令（`rm`、`mv`、`cp`），检查点追踪不到，回退也恢复不了。只有它用"编辑文件"方式做的改动才能回退
- **你自己手动做的改动**、其他会话做的改动，通常也不在追踪范围
- **子代理做的改动**多数不会恢复（见 [3.11](/advanced/agents)）
- 检查点保留约 30 天，且只保留最近 100 个
- 检查点**不能代替备份**

所以重要原始资料一定要**先复制一份**，或者要求它"不要修改原文件，结果放新文件夹"。

## 五、Plan 模式：先出方案，再动手

Plan 模式让 Claude **只看、只想、只写方案，不改你的文件**。方案你认可之后，才开始执行。适合：

- 任务大、涉及很多文件
- 你不确定它会怎么做
- 对结果要求高，不想"改完再推翻"

**怎么进入**：

- VS Code：点击输入框底部的模式指示器，选 **Plan**；或者在输入框直接输入 `/plan`（需 v2.1.280 及以上）。`/plan 任务描述` 可以进入 Plan 模式并直接开始规划，`/plan open` 可在编辑器中打开方案文件
- 终端：按 `Shift+Tab` 循环切换模式，或启动时用 `claude --permission-mode plan`

在 VS Code 里，方案会自动在编辑器中以文档形式打开，你可以直接在上面**添加批注**，再让它按批注修改，满意后批准执行。

```text
/plan 我想把【访谈记录】里的 30 份文档整理成汇总表，并按"部门"和"关注问题"两个维度做统计。
请先给出方案：打算怎么分步骤做、会新建哪些文件、会不会改动原文件、有哪些信息可能缺失。
```

看完方案，常见的回应有三种：同意并执行；要求调整某一步；让它列出更多备选方案。

## 动手任务

用"练习-调研资料"文件夹：

1. 切到 Plan 模式，让它规划"把所有文件整理成汇总表并写一份 300 字摘要"，在方案上提出一处修改意见
2. 批准后执行，在 Manual 模式下观察对比视图
3. 故意让它做一件不太对的事，例如"把摘要里的第一个数字改成 100"，然后用回退功能恢复
4. 检查恢复后的文件，确认回到了改动之前

## 小结

- 布置任务时写清范围、目标、格式和边界，最好声明"不改原文件"
- 看对比、核对结果，是日常使用的核心习惯
- 回退能撤销"编辑文件"的改动，但管不了命令行的删除和移动，也不是备份
- 大任务先用 Plan 模式出方案
