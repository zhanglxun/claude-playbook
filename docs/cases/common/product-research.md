# 产品调研分析

产品调研的目的是回答一个问题：**这款产品到底该怎么卖？** 把产品资料交给 Claude，可以在几分钟内得到一份结构清晰的初稿，你再在此基础上判断和修正。

> 下文案例为虚构：某家居出海品牌的"静音折叠收纳凳"（示意产品，数据均为示意）。

## 分析框架

1. **产品是什么**：功能、规格、材质、适用场景。
2. **卖给谁**：目标用户画像、使用场合、购买动机。
3. **为什么买**：核心卖点，与同类产品的差异。
4. **有什么问题**：用户痛点、常见顾虑、可能的差评点。
5. **还缺什么**：资料里没有、需要补充或核实的信息。

第 5 点最容易被忽略。让 Claude 主动列出"资料不足之处"，能避免它顺着空白处编造。

## 示范提示词

### 基础版：一份资料出初稿

先上传产品说明书或产品介绍文档，再发送：

```text
你是一名资深产品经理。我上传了【产品名称】的资料，请严格依据资料内容，按以下框架分析：
1. 产品定位（一句话）
2. 目标用户画像（3 类，每类写：人群特征、使用场景、购买动机）
3. 核心卖点（5 条，按重要性排序，每条注明依据来自资料的哪一部分）
4. 可能的用户顾虑及应对话术（至少 4 条）
5. 资料中缺失、需要我补充或核实的信息

要求：
- 资料里没有的信息不要编造，写"待确认"
- 用表格输出第 2、3、4 项
- 最后用 3 句话总结这款产品最值得主推的方向
```

### 进阶版：追问深化

```text
针对你列出的第 2 类用户【用户类型】，请：
1. 站在这类用户角度，写出他们购买前最可能搜索的 5 个问题
2. 为每个问题写一句 30 字以内的回答，可用于产品详情页
3. 标出哪些回答需要产品数据支撑，我会去核实
```

## 课堂练习

1. 选一款自家产品（或用本页虚构产品），用基础版提示词出一份初稿。
2. 检查"核心卖点"中哪些确实来自资料，哪些是 Claude 的推测，用笔标出来。
3. 用进阶版追问一类用户，对比前后结果的差别。

## 注意事项

- **资料质量决定结果质量**：资料零散，结果也会空泛。先补充产品参数再分析。
- **应对话术要核实**：涉及性能参数、认证、保修等承诺，必须由负责人确认，不要直接对外使用。
- **公开资料为主**：不要上传尚未公开的研发资料、成本价等敏感信息；需要用时先脱敏。

## 两种做法对照

### 网页版做法

- 上传 1 到 3 份产品资料（PDF、Word、Excel 均可）。
- 用基础版提示词出初稿，再对话追问。
- 同一产品长期分析，建立一个 [Projects](/basics/projects)，把资料放进项目知识库，把分析框架写进项目指令。
- 适合：单款产品、资料不多。

```text
请阅读我上传的产品资料，按"产品定位、目标用户、核心卖点、用户顾虑、待确认信息"五部分写一份调研初稿，用表格输出，资料中没有的内容写"待确认"。
```

### Claude Code 做法

- 把全部产品资料放进一个文件夹，例如 `产品资料/`，一次让它读完。
- 让它按固定格式生成汇总表和报告文件，不用逐个上传。
- 在文件夹放一份 `CLAUDE.md` 写明分析框架和输出要求，每次自动遵守；固定流程可做成 [Skills](/advanced/skills)。
- 适合：几十款产品要各出一份分析、每月重复更新。

```text
请读取当前文件夹 产品资料/ 下的所有 PDF 和 Word 文件，每个文件对应一款产品。
对每款产品按"产品定位、目标用户、核心卖点、用户顾虑、待确认信息"整理，
把全部产品汇总为一张表，保存为 产品调研汇总.xlsx；
再为每款产品各写一份分析报告，保存到 报告/ 文件夹，文件名用产品名。
资料中没有的信息写"待确认"，不要编造。完成后告诉我哪些产品资料不足。
```

了解更多：[Claude Code 是什么](/advanced/what-is-claude-code)、[CLAUDE.md](/advanced/claude-md)。

## 小结

产品调研 = 框架 + 资料 + "不编造"的约束。先出初稿，再由人判断卖点是否站得住。
