# Claude Code 模板

本页提供三类可直接改用的模板：`CLAUDE.md`（给 Claude Code 的"工作说明书"）、`SKILL.md`（可复用的"技能"）、常用任务提示词。模板中的公司均为虚构。

概念和原理请先读：[CLAUDE.md 记忆文件](/advanced/claude-md)、[Skills 技能](/advanced/skills)。

::: tip 通用原则
- CLAUDE.md 每次会话都会被读取，要**短**：只写规则和约定，不写长篇资料。
- 不要在里面写密码、账号、客户隐私，参见 [使用规范与数据安全](/security/)。
- 写得越具体越好用："周报不超过一页"比"周报要简洁"有效。
:::

## 一、CLAUDE.md 模板

放在工作文件夹的根目录，文件名固定为 `CLAUDE.md`。

### 模板 1：调研资料库

**用途**：文件夹里放着一个主题的调研资料（报告、网页存档、访谈记录），让 Claude 协助整理和分析。

```text
# 调研资料库：智能家居收纳（虚构示例，星河家居）

## 这个文件夹是什么
- 用于研究"智能家居收纳"品类，读者是公司产品委员会。
- raw/ 放原始资料（不要修改）；notes/ 放整理后的笔记；output/ 放最终报告。

## 工作规则
- 只读 raw/，不得修改或删除其中任何文件。
- 所有结论必须标注出处（文件名 + 页码或段落）；没有出处的内容标"推测"。
- 数据冲突时并列列出，不要自行取舍。
- 新建的文件放在 notes/ 或 output/，文件名用"日期_主题"，例如 2026-10-18_竞品价格带.md。

## 输出约定
- 中文，面向非技术管理层，少用术语。
- 报告结构：摘要（不超过 200 字）→ 关键发现 → 依据 → 待核实问题。
```

**怎么改**：替换主题和公司；按实际文件夹名修改目录说明；读者不同就改"输出约定"；如果资料很多，加一行"新增资料后，先更新 notes/索引.md"。

### 模板 2：周报助手

**用途**：每周把零散记录整理成固定格式的周报。

```text
# 周报助手（虚构示例，晨光贸易 销售运营组）

## 文件夹说明
- records/ 放每周的工作记录（聊天摘录、待办清单）；
- template.md 是周报模板，必须严格按它的结构写；
- reports/ 放已生成的周报。

## 工作规则
- 生成周报时，先读 template.md，再读 records/ 里本周的文件。
- 只写记录里有的事情；不明确的地方列在文末"待确认"，不要编造数据。
- 每条"完成事项"必须带结果（数字或状态）。
- 参考 reports/ 里上周的周报，保持语气一致，"下周计划"要对上上周的遗留事项。
- 生成后保存到 reports/，文件名：YYYY-MM-DD_周报.md。

## 禁止
- 不得写入客户全名，用"客户 A、客户 B"代替。
```

**怎么改**：换成自己的部门；调整"禁止"中的脱敏规则；在 template.md 里放你们真实的周报格式。

### 模板 3：销售资料库

**用途**：整理产品资料、报价说明、常见问答，帮助销售快速写方案和邮件。

```text
# 销售资料库（虚构示例，蓝岸机电）

## 内容
- products/ 产品规格与卖点（已审核）；
- faq/ 客户常见问题及标准答复；
- cases/ 可对外使用的案例（已去除客户信息）；
- drafts/ 草稿区，Claude 的产出先放这里。

## 规则
- 对外内容只能引用 products/、faq/、cases/ 里的信息。
- 资料里没有的参数、交期、价格，一律回答"需与业务确认"，不得推测。
- 不写具体报价和折扣；需要时留空并标注【待业务填写】。
- 每份草稿末尾列出"引用了哪些文件"，方便审核。

## 语气
- 对外专业、礼貌、简洁；中文邮件不超过 300 字，英文邮件不超过 150 词。
```

**怎么改**：按实际目录改；如果有多个产品线，在 products/ 下分子文件夹并写明；加入你们的"禁用词"清单（如绝对化用语）。

技能是一个文件夹，里面有一个 `SKILL.md`。文件头部的 `name` 和 `description` 决定 Claude 何时使用它，所以 `description` 要写清"什么情况下用"。

### 技能 1：会议纪要整理

**用途**：把会议记录整理成统一格式的纪要。放在 `.claude/skills/meeting-minutes/SKILL.md`。

```text
---
name: meeting-minutes
description: 把会议记录、录音转写整理成结构化会议纪要。当用户提到"整理会议纪要""会议记录"时使用。
---

# 会议纪要整理

## 步骤
1. 读取用户提供的会议记录文件。
2. 提取：会议主题、日期、参会人、讨论要点。
3. 区分"已决定的事项"和"仍在讨论的事项"，分别列出。
4. 生成待办表：事项 | 负责人 | 截止时间。负责人或时间不明确时写"待确认"。
5. 保存为 Markdown 文件，文件名：YYYY-MM-DD_会议主题_纪要.md。

## 规则
- 只依据原文，不补充没有说过的内容。
- 纪要不超过一页。
- 结尾列出"需要用户确认的问题"。
```

**怎么改**：把"步骤"换成你们公司纪要的实际格式；想要英文纪要就在规则里写明语言；可附一份范例文件让输出更稳定。

### 技能 2：客户询盘回复草稿

**用途**：根据询盘邮件和产品资料，起草回复。

```text
---
name: inquiry-reply
description: 根据客户询盘邮件和产品资料起草回复邮件。当用户提到"回复询盘""写报价回信"时使用。
---

# 询盘回复草稿

## 步骤
1. 读取客户邮件，列出客户提出的全部问题和需求。
2. 到 products/ 和 faq/ 中查找答案，只使用其中已有的信息。
3. 起草回信：感谢 → 逐条回答 → 明确下一步。
4. 资料里没有的内容，写"我们将确认后答复"，并在草稿外单独列出"需要业务确认的事项"。

## 规则
- 不写价格、折扣、交期承诺。
- 语言与客户来信一致；英文不超过 150 词。
- 草稿保存到 drafts/，不要直接发送。
```

**怎么改**：调整资料目录；加入公司签名格式；把不能承诺的事项按你们规定补全。

### 技能 3：周报生成（可选）

如果你已经有[周报助手](#模板-2-周报助手)，可以把"读 template.md → 汇总 records/ → 保存"的步骤做成技能 `weekly-report`，写法同上，这样换一个文件夹也能复用。

## 三、常用任务提示词

在 Claude Code 里输入。可用 `@文件名` 指定文件。

整理文件夹（先让它列方案，再动手）：

```text
请看一下【文件夹名】里有哪些文件，提出整理方案：新的目录结构、每个文件的新名字。
先只给方案，不要移动或改名。我确认后再执行。
```

批量处理资料：

```text
请阅读 【文件夹】里所有 PDF，为每份生成一份 300 字以内的摘要，
保存到 notes/ 下，文件名与原文件同名。最后生成一份索引表：文件名 | 主题 | 一句话结论。
不要修改原文件。
```

读表格出报告：

```text
请读取 @【表格文件.xlsx】，按【维度】汇总【指标】，生成一份 Markdown 报告保存到 output/。
计算方法请写在报告末尾。发现数据异常先告诉我，不要自行修正。
```

先规划再执行（大任务）：

```text
这个任务比较复杂：【任务描述】。
请先进入规划，给出步骤、会读取和修改哪些文件、可能的风险。我批准后再开始。
```

核对与自查：

```text
请检查你刚才生成的【文件】：
1. 每个数据是否都能在原资料中找到出处？列出找不到出处的；
2. 是否有与原资料矛盾的地方？
3. 有没有违反 CLAUDE.md 里的规则？
```

新建 CLAUDE.md：

```text
请先浏览当前文件夹，然后帮我起草一份 CLAUDE.md，说明这个文件夹的用途、目录结构和工作规则。
先给草稿，不要直接保存；写完后列出你不确定、需要我补充的地方。
```

**怎么改**：把【】换成实际文件和目录；风险较大的操作（删除、覆盖）一律要求"先给方案"；用法细节见 [日常使用](/advanced/daily-use) 与 [权限与安全](/advanced/permissions)。
