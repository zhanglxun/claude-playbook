# 权限与安全

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 说清 Claude Code 默认能做什么、哪些动作必须先问你
- 区分常见的权限模式，并按任务风险选模式
- 理解"自动模式"是怎么回事，以及它的边界
- 用规则保护敏感文件，养成安全的使用习惯

## 一、为什么要有"权限"

Claude Code 能读、能改、能删你电脑上的文件，还能运行程序。这很强大，但也意味着：**如果它理解错了你的意思，后果会真实发生在你的文件上。** 所以它有一套"权限"机制，决定哪些动作可以直接做，哪些必须先问你。

默认情况下的大致规则：

| 动作 | 是否需要问你 |
|---|---|
| 读取工作文件夹里的文件 | 通常不需要 |
| 修改、新建文件 | 取决于权限模式 |
| 运行命令（Bash 命令） | 除一批只读的安全命令外，通常需要 |
| 访问网页 | 通常需要，少数官方文档域名除外 |

## 二、权限模式

**权限模式**决定"在你不点同意的情况下，它能做到哪一步"。下表中的名称以 VS Code 面板为准，括号是配置文件里使用的值。

| 模式 | 不问你就能做的事 | 适合场景 |
|---|---|---|
| **Manual**（每步确认，值为 `default`） | 只能读取 | 敏感工作、不熟悉的资料、刚开始学习 |
| **Edit automatically**（自动批准编辑，值为 `acceptEdits`） | 读取、修改文件，以及新建文件夹、移动复制等常见文件操作 | 你打算事后统一检查修改 |
| **Plan**（先规划，值为 `plan`） | 只读取和探索，写方案，不改文件，方案批准前不动手 | 大任务、不确定怎么做时 |
| **Auto**（自动模式，值为 `auto`） | 几乎所有事，但有后台安全审查 | 长任务、不想被反复打断 |

除此之外还有两个你**一般不会用到**的模式：`dontAsk`（遇到要问的一律拒绝，用于自动化脚本）和 `bypassPermissions`（跳过所有检查，官方仅建议在隔离的容器或虚拟机里使用）。**业务人员不要使用 `bypassPermissions`。**

### 怎么切换

- **VS Code**：点击输入框底部的模式指示器，选模式
- **终端**：按 `Shift+Tab` 循环切换，状态栏会显示当前模式；启动时也可以用 `claude --permission-mode plan` 这样指定

## 三、自动模式（新会话默认）

自动模式是这一代 Claude Code 里最大的变化之一，请重点理解。

**它是什么**：在自动模式下，每个动作执行前，会有**另一个 AI 模型（称为"分类器"）**做安全审查。看起来没问题的动作直接放行；超出你要求范围、涉及不认识的外部系统、或看起来像是被网页里的恶意内容"带偏"的动作，会被拦下，Claude 会收到拦截原因后换做法。

**什么时候默认**：需 Claude Code v2.1.283 及以上，终端和 VS Code 里**新开的会话默认进入自动模式**（各套餐和接入方式均适用）。更早的版本，只在 Pro、Max、Team 套餐上默认。这也意味着，你装好后第一次对话，很可能已经在自动模式里，请先看一眼模式指示器。

**它有条件**：需要受支持的模型（例如 Claude Sonnet 5.5、Claude Opus 5.5、Claude Haiku 5.5 以及 Claude Fable 5.1 一类较新的模型）；组织管理员可以关闭它；若所在组织采用了特殊合规配置，则默认回到 Manual。如果界面里没有 Auto 选项，就是不可用，会自动回到 Manual。模型详情见 [3.8 模型选择与推理强度](/advanced/models)。

**它的边界，务必记住**：

- 官方明确说明：自动模式**减少了确认提示，但不保证安全**。适合你信任大方向的任务，**不能代替你对敏感操作的审查**
- 你明确设置的"询问"规则仍然会弹出确认
- 一些高危动作在任何模式下都不会被自动放行，比如删除家目录、工作目录这类关键路径的 `rm` 命令
- 它会"推着 Claude 尽量不停下来问问题"，所以任务描述要清楚

**业务人员怎么选**：

| 任务 | 建议模式 |
|---|---|
| 刚学习、第一次处理某类文件 | Manual |
| 整理资料、生成报告（输出到新文件夹） | Auto，加上"不改原文件" |
| 要改动重要原始文件 | Manual，或先备份再 Edit automatically |
| 大型、复杂的任务 | 先 Plan，再换 Auto 执行 |

## 四、受保护的文件和文件夹

有一小批路径，即使在宽松模式下也**不会被自动批准写入**，以防 Claude 的配置或你的环境被意外改坏。例如：

- 版本管理和编辑器配置文件夹：`.git`、`.vscode`、`.idea` 等
- Claude 自己的配置：`.claude`（少数例外，如自己的计划文件）、`.mcp.json`、`.claude.json`
- 系统和工具配置：`.zshrc`、`.bashrc`、`.gitconfig` 等

在 Manual 和 Edit automatically 模式下，写这些位置会弹窗询问；在自动模式下交给分类器判断；在 `dontAsk` 模式下直接拒绝。你日常的业务文档不受影响。

## 五、保护你的敏感文件

"受保护路径"保护的是配置，**你自己的敏感业务文件（合同、报价、客户名单、账号信息）需要自己设规则**。

### 方式一：不要让它看到

最彻底的办法是**不要放在工作文件夹里**。工作文件夹只放这次任务需要的资料。

### 方式二：设置"禁止读取"规则

可以用"拒绝规则"告诉 Claude Code 不得读取某些文件。规则的判断顺序是 **拒绝 → 询问 → 允许**，命中第一条就定结果，所以拒绝规则优先级最高，任何模式下都有效。

在输入框里输入 `/permissions`，会打开管理界面，可以查看、添加、删除规则。也可以直接让 Claude 帮你，例如：

```text
请帮我在项目设置里添加"禁止读取"规则，保护：
- 【合同】文件夹下的所有文件
- 所有名字以 .env 结尾的文件
```

规则本身长这样（了解即可，保存在工作文件夹的 `.claude/settings.json` 里）：

```json
{
  "permissions": {
    "deny": [
      "Read(./合同/**)",
      "Read(./.env)"
    ]
  }
}
```

注意几点：

- 读取类的拒绝规则对 Claude 内置的文件工具有效，对它在命令行里读文件的常见做法（如 `cat`）也有效；官方同时说明，对"不点名文件的间接读取"（例如在整个目录里搜索）覆盖有限，**所以不能把它当作绝对保险**
- 官方明确说过：`.claudeignore` 文件**不起作用**，请改用上述规则
- 拒绝规则不能解决"文件已经在文件夹里，但你不想外传"的所有问题，最稳妥的仍是方式一

### 方式三：操作习惯

- 每次只打开**最小范围**的文件夹
- 批量改动前先**备份**
- 对删除类操作保持警惕：看到 `rm`、"删除""覆盖"字样，停下来读清楚
- 不要把账号密码、密钥直接写进对话或文档让它处理
- 让它处理网页或外部资料时，留意其中可能夹带"指令"（提示注入）；自动模式对此有防护，但不是万能
- 遵守 [使用规范与数据安全](/security/) 里的规则：客户信息、合同金额等不得放入

## 六、遇到确认弹窗怎么选

典型的弹窗有这些选项：

| 选项 | 含义 | 建议 |
|---|---|---|
| Yes | 仅这一次同意 | 默认选择 |
| Yes, and don't ask again | 同意并记住 | 仅对你完全理解且重复的操作选；对命令这类选择会**永久**记在该项目里 |
| No | 拒绝，并可以告诉它换做法 | 不确定时选这个 |
| Yes, and switch to auto mode | 同意并切到自动模式（命令确认时出现） | 想放手就选，需 v2.1.247 及以上 |

## 课堂练习

1. 在"练习-调研资料"文件夹中，把模式切到 **Manual**，让 Claude 新建一个文件，对比观察确认弹窗
2. 切到 **Auto**，让它做同样的事，比较体验差异
3. 在文件夹中新建一个"合同"子文件夹，放入一份虚构的合同，设置一条禁止读取规则，然后让 Claude 总结这个文件夹，观察结果
4. 讨论：你们团队的哪些文件必须永远放在工作文件夹之外？

## 小结

- 权限模式从严到松：Manual → Edit automatically → Auto；Plan 是"只想不做"
- 新会话默认进入自动模式（需 v2.1.283 及以上），它有安全审查但不保证安全，重要操作仍要自己把关
- 敏感文件的最佳保护：不放进工作文件夹；其次是设禁止读取规则
- 永远不要对业务工作使用 `bypassPermissions`
