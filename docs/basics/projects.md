# Projects 项目功能

学完这页，你能建立一个长期可用的"项目"，把资料和固定要求放进去，让以后每次对话都不用重复交代背景。

## 是什么

每次新开对话，Claude 都不记得以前聊过什么。如果每次都要重新粘贴公司介绍、写作要求，既麻烦又容易漏。

**Projects（项目）** 就像给某类工作设一个专属工作间，里面有两样东西：

| 组成 | 作用 | 类比 |
|---|---|---|
| 项目知识库 | 存放你上传的文件和文本资料 | 放在工作间书架上的资料 |
| 项目指令 | 一份固定说明，告诉 Claude 在这个项目里怎么做事 | 贴在墙上的岗位说明 |

在项目里开的每个新对话，都会自动带上这些资料和指令。项目里的对话也会集中保存在一起，方便查找。

## 适合放什么

- 公司介绍、产品目录、常见问答（脱敏后）
- 写作风格要求，例如邮件语气、品牌用语、禁用词
- 某个市场或客户类型的长期调研资料
- 固定的报告模板、周报模板

不要放：客户真实联系方式、合同金额、报价底线等敏感资料。详见 [使用规范与数据安全](/security/)。

## 建议的项目划分

| 项目 | 放入的资料 |
|---|---|
| 产品知识库 | 产品手册、规格表、卖点 |
| 市场调研 | 目标市场报告、竞品资料 |
| 外贸沟通 | 邮件模板、公司介绍、常见问答 |
| 周报助手 | 周报模板、往期周报样例 |

划分原则：**一个项目对应一类长期工作**。资料太杂会互相干扰，宁可多建几个小项目。

## 创建一个项目的步骤

1. 在左侧边栏进入 Projects，点击新建项目。
2. 起一个清晰的名字，例如"外贸邮件助手"。
3. 添加项目指令（见下方示例）。
4. 上传知识库文件。
5. 在项目内新建对话，开始使用。

界面按钮名称可能随版本调整，以实际界面为准。

## 项目指令怎么写

指令要像岗位说明：身份、任务范围、风格、禁区。

```text
你是【公司名称】的外贸邮件助手。
服务对象：欧洲地区的经销商客户。
任务：根据我给的要点撰写或润色英文邮件。
风格：专业、简洁、礼貌，不使用夸张用语。每封邮件不超过 150 词。
规则：
1. 只使用知识库中的产品信息，不要编造参数。
2. 涉及价格、交期时，用【待确认】占位，由我填写。
3. 不确定时先问我。
```

## 示例：周报助手

1. 新建项目"周报助手"。
2. 上传周报模板和一份往期样例。
3. 指令写明：每周我会给你零散的工作记录，请按模板整理，突出本周成果、问题、下周计划。
4. 第一周：在项目里开新对话，粘贴工作记录，生成周报。
5. 第二周：再开一个新对话，同样粘贴，不用重新交代模板。

这就是 Projects 的价值：**一次设置，反复使用。**

## 维护小贴士

- 资料更新后，删除旧文件再上传新版，避免新旧并存。
- 指令发现不好用，就直接修改，不用新建项目。
- 定期检查知识库里是否混入了敏感信息。
- 重要输出仍需人工核对，知识库不等于一定正确。

## 课堂练习

用 Projects 搭一个"周报助手"：上传模板，连续生成两周周报，对比两次的格式是否一致，并调整一次项目指令。

## 小结

- Projects = 知识库 + 项目指令，让对话自带背景。
- 一类长期工作建一个项目，资料脱敏后再放。
- 指令写成岗位说明，用得不好就修改。
