# Claude Tag：在 Slack 里指派 Claude

> 内容核对日期：2026-10-18；选学内容。部分功能为研究预览/公测，且按套餐和版本开放，请以官方文档为准。

**了解即可**：本页只做概念介绍，不涉及配置步骤。

## 它是什么

Claude Tag 把 Claude 放进你们团队的 **Slack 频道**里。频道里的同事在消息中 `@Claude`，交给它一件事，它会在帖子的讨论串里回复，发一份进度清单，做完把结果贴回来。整个过程在频道里公开可见，大家都能看到它做了什么。

可以把它理解为：**一位坐在群里、随时接活的 AI 同事**。

## 典型用法

- 把一个吵了半天的讨论串整理成决策文档或客户回复。
- 在需求或问题收集频道里回答能回答的问题，识别重复问题，其余分派给相关负责人。
- 用自然语言问数据问题，由它查询并生成图表（需要接入数据仓库）。
- 定期汇总项目状态，跟进审批进度。
- 在技术团队，报告问题后生成修复的拉取请求草稿。

它能接触什么，取决于管理员给这个频道接入了哪些外部服务；不确定时，直接问它：`@Claude 你在这个频道能访问哪些东西？`

## 适用范围与计费

- **套餐**：适用于 Team 和 Enterprise；个人套餐（Free、Pro、Max）不适用。
- **状态**：**公测**（Public Beta），功能和规则可能变化。
- **配置**：由组织的 **Owner（所有者）或管理员**一次性完成，把 Slack 工作区与 Claude 组织配对；普通成员无需安装，也无需逐个配置。
- **计费**：频道里的工作**按用量计费**，从组织的用量余额中扣除，管理员可设置消费上限；不是按席位另收费。具体规则以官方页面为准：[Claude Tag 官方文档](https://claude.com/docs/claude-tag)。

## 使用前要想清楚的事

- Claude 干活的环境是临时隔离的沙箱，不是你的电脑。
- 频道里的内容会成为它的工作上下文，涉及敏感资料的频道需先由管理员确认访问范围。
- 它产出的文档、数据、代码改动，仍然要人工核对后再用。
- 是否开通、接入什么，是公司管理层和管理员的决定，不建议个人自行尝试。

## 小结

Claude Tag 是"团队共享的 Claude"：在 Slack 频道里 `@Claude` 交活，结果留在讨论串里，适用 Team/Enterprise，由管理员配置，按用量计费，目前处于公测。
