# 记忆与规则：CLAUDE.md

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 说清为什么每次新对话它都"不记得你"，以及怎么解决
- 为自己的工作文件夹写一份 CLAUDE.md
- 区分项目级和个人级说明，知道自动记忆是什么
- 用 `/init` 和 `/memory` 生成、查看和修改记忆

## 一、问题：它每次都是"新人"

Claude Code 的每个会话开始时，都带着一张**白纸**。你昨天花十分钟讲清楚的业务背景、写作习惯、格式要求，今天新开一个对话，它全不记得了。

官方提供两种机制，让知识能跨对话保存下来：

| | CLAUDE.md | 自动记忆（auto memory） |
|---|---|---|
| 谁写 | **你** | **Claude 自己** |
| 内容 | 指令和规则 | 它从你的纠正和偏好中学到的东西 |
| 范围 | 项目、个人或组织 | 每个项目一份，存在你的电脑上 |
| 什么时候读 | 每次会话开始 | 每次会话开始（只读开头的 200 行或 25KB） |

两者都是以"背景资料"的方式交给 Claude 参考，**不是强制命令**。写得越具体、越简短，它遵守得越稳定。

## 二、CLAUDE.md 是什么

**CLAUDE.md** 就是一个普通的文本文件（Markdown 格式），名字固定叫 `CLAUDE.md`。你可以把它理解为**"给新来的助理的工作交接手册"**：这是什么项目、我们怎么做事、有哪些禁忌。

它在每次会话开始时自动读入，所以你不需要每次重新交代。

### 放在哪里

| 类型 | 位置 | 管谁 |
|---|---|---|
| 个人级 | `~/.claude/CLAUDE.md` | 你的所有项目 |
| 项目级 | 工作文件夹根目录的 `CLAUDE.md`（或 `.claude/CLAUDE.md`） | 这个文件夹，同事共享时可以一起带走 |
| 个人项目级 | 工作文件夹里的 `CLAUDE.local.md` | 只你在这个文件夹，不想共享的私人偏好 |
| 组织级 | 由管理员统一部署 | 全公司 |

它会从你启动的文件夹往上逐层查找，找到的文件都会读入，叠加使用，不是互相覆盖。子文件夹里的 CLAUDE.md 则是 Claude 读到该子文件夹里的文件时才加载。

**业务上怎么用**：个人级放你的通用习惯（"用中文回答，先结论后细节"）；项目级放这个资料库特有的规则。

## 三、一个业务例子：调研资料库

假设你是虚构公司"云帆咨询"的调研员，有一个长期维护的调研资料库文件夹。可以在根目录放这样一个 `CLAUDE.md`：

```markdown
# 云帆咨询 · 行业调研资料库

## 这个文件夹是什么
存放各行业调研的原始资料和成果，供分析员写报告使用。

## 文件夹结构
- 01-原始资料/  访谈记录、公开报告、新闻剪报（只读，不要修改）
- 02-整理/      资料摘要、汇总表（Claude 的主要输出位置）
- 03-报告/      正式报告终稿（只在我明确要求时才修改）
- 模板/         报告模板、汇总表模板

## 工作规则
- 永远不要修改"01-原始资料"里的任何文件
- 新生成的文件放进"02-整理"，文件名格式：日期_主题，如 20261018_竞品汇总.md
- 引用任何数据，必须注明来自哪个文件的哪一部分
- 资料里没有的信息写"资料未提及"，不要推测或编造
- 涉及数字的地方，列出原文再给结论，方便我核对

## 写作要求
- 用中文，面向非技术的管理层
- 先写结论，再写依据
- 一段不超过 5 行，多用表格
- 术语第一次出现时用括号解释

## 常用任务
- "汇总" = 读取指定文件夹，输出一张表：来源、要点、可信度
- "对比" = 按"价格、功能、服务、风险"四个维度比较，用表格

## 需要先问我的情况
- 要删除或移动文件
- 资料之间出现矛盾
- 需要联网查找新信息
```

### 怎么写得好

官方的建议和我们的实践一致：

- **控制长度**：每个文件建议不超过 200 行。越长越占空间，遵守度也越低
- **具体可核对**：不要写"整理得好一点"，要写"表格列为 A、B、C"
- **只写长期有效的规则**：一次性任务的要求不要放进去
- **不要自相矛盾**：新旧规则冲突时，它可能随机选一个
- **不要放机密**：CLAUDE.md 会读入对话，也常随文件夹共享。账号、密码、客户机密一律不要写
- **可以引用别的文件**：在 CLAUDE.md 里写 `@模板/周报模板.md`，该文件内容会一起读入（最多嵌套四层）。如果只是在文字里提到路径而不想引入，用反引号括起来

::: tip 写完用一个问题检验
新开一个对话，问："你对这个文件夹有哪些了解？列出你会遵守的规则。"看它的回答是否符合你的预期。
:::

## 四、用 `/init` 快速生成

不用从零写。在工作文件夹里打开 Claude Code，输入：

```text
/init
```

它会读你的文件夹，生成一份起始版 CLAUDE.md。生成后你要做的是**逐条核对和精简**：删掉它猜错的，补上它不可能知道的业务规则（如"原始资料不能改"）。

`/init` 最初是面向代码项目设计的，对业务资料夹可能生成偏技术化的内容，需要你自己调整，也可以直接告诉它：

```text
请根据这个文件夹的实际内容，为我生成一份 CLAUDE.md。
这不是代码项目，是一个行业调研资料库。请包含：文件夹结构、命名规则、
哪些文件不能改、写作要求。控制在 60 行以内，不要写代码相关的内容。
```

## 五、用 `/memory` 查看和修改

输入 `/memory` 可以：

- 看到当前加载了哪些 CLAUDE.md 文件（个人级、项目级）
- 点击某个文件，在编辑器里打开修改；不存在的会先帮你创建
- 打开或关闭**自动记忆**
- 打开自动记忆文件夹，查看它记了什么

想确认某次对话里到底加载了哪些说明，输入 `/context` 查看。

**直接口头吩咐也可以**：你说"记住：以后汇总表都按日期倒序"，它会存进自动记忆；如果想存进 CLAUDE.md，要明说"请把这条加到 CLAUDE.md"。

## 六、自动记忆

**自动记忆**是 Claude 自己记笔记。你纠正它、说出偏好时，它会判断"这对以后有用吗"，有用的才记。笔记大致分四类：关于你的（角色、专长）、反馈（你纠正过的做法）、项目（进行中的工作、决定）、参考（去哪里找资料）。

要点：

- **默认开启**（本地会话）。可以在 `/memory` 里关闭
- 存放位置：你电脑上的 `~/.claude/projects/<项目>/memory/`，只在这台电脑上，不会同步到别的电脑
- 里面有一个目录文件 `MEMORY.md`，每次会话开始读它的前 200 行（或 25KB）；详细笔记放在别的主题文件里，需要时才读
- 工作时你可能看到 "Saved 2 memories" 或 "Recalled 2 memories" 的提示，表示它在写或读记忆
- 这些都是普通文本文件，**你可以随时打开查看、修改或删除**。如果它记错了，直接改或让它忘掉
- 记忆文件夹是机器本地的，换电脑要重新积累

**两者怎么配合**：稳定的、你要它必须遵守的规则，写进 CLAUDE.md；零碎的、随用随学的偏好，交给自动记忆。定期（比如每月）打开 `/memory` 检查一遍，清理过时的内容。

## 七、其他可能遇到的情况

- **AGENTS.md**：另一类 AI 工具使用的类似说明文件。需 v2.1.277 及以上时，如果文件夹里只有 AGENTS.md 而没有 CLAUDE.md，Claude Code 会改读 AGENTS.md；两者都有时只读 CLAUDE.md。你不必刻意去建
- **对话压缩之后**：对话变长被压缩时，根目录的 CLAUDE.md 和自动记忆会重新从磁盘读入，不会丢；但只在子文件夹里触发的说明可能要重新触发（见 [3.7](/advanced/context-usage)）
- **它没有照做**：先检查 CLAUDE.md 是否太长、是否有矛盾，再用 `/context` 确认文件确实被加载了。要"绝对禁止"的事，别只靠 CLAUDE.md，用 [3.5 权限与安全](/advanced/permissions) 里的拒绝规则，或选学的 [Hooks](/advanced/optional/hooks)

## 动手任务

1. 在"练习-调研资料"文件夹里，用 `/init` 或让 Claude 帮你生成一份 CLAUDE.md
2. 手动补写三条你的业务规则（例如"原始资料不可改""数据必须注明出处""找不到就写资料未提及"）
3. 用 `/clear` 开一个新对话，让它"汇总所有文件"，检查它是否遵守了规则
4. 在对话中纠正它一次（如"以后文件名都加日期前缀"），然后输入 `/memory` 看它是否被记下来

## 小结

- CLAUDE.md 是写给 AI 的"工作交接手册"，每次会话自动读入，解决"每次都要重新交代"
- 项目级放这个资料库的规则，个人级放通用习惯；保持简短、具体、无矛盾
- 自动记忆由 Claude 自己写，默认开启，你可以用 `/memory` 随时查看和修改
- 它们是参考而不是强制，真正的禁止要靠权限规则
