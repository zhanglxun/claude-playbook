# Skills：把做事流程固化

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 说清 Skills（技能）是什么，和 CLAUDE.md、普通提示词有什么区别
- 自己写出一个业务技能（以"调研报告生成"为例）并放到正确的位置
- 手动调用技能，或让 Claude 在合适时自动使用
- 用 `/skill-doctor` 检查技能的"开销"和使用情况
- 知道插件是打包分享技能的方式

## Skills 是什么

**技能（Skill）就是一份"做事手册"**：你把某类工作的步骤、格式要求、注意事项写成一个文件，Claude 需要时就读它，照着做。

对比一下：

| | 是什么 | 什么时候读 |
|---|---|---|
| 提示词 | 你这一次说的话 | 当次 |
| CLAUDE.md | 项目的"常驻说明书"（见 [CLAUDE.md](/advanced/claude-md)） | 每次对话开头都读 |
| Skill | 某项具体工作的"操作手册" | 用到时才读全文 |

好处有三个：**不用每次重复讲一遍**；**团队产出格式一致**；**不占用平时的"工作记忆"**（平时只放一行简介，用到才读全文，上下文的概念见[上下文与用量管理](/advanced/context-usage)）。

适合做成技能的工作：每周都要写的周报、统一格式的调研报告、客户来信的回复规范、资料的整理归档规则。

## 技能放在哪里

一个技能就是一个**文件夹**，里面必须有一个叫 `SKILL.md` 的文件。常用的两个位置：

| 位置 | 路径 | 谁能用 |
|---|---|---|
| 个人技能 | `~/.claude/skills/技能名/SKILL.md` | 你在这台电脑上的所有项目 |
| 项目技能 | 工作文件夹里的 `.claude/skills/技能名/SKILL.md` | 在这个工作文件夹里开的对话（放进共享的项目里，同事也能用） |

说明：`~` 代表你电脑上的"用户主目录"；以点开头的文件夹（如 `.claude`）在 Mac 访达里默认隐藏，按 `Command + Shift + .` 可显示。最省事的办法是**直接让 Claude 帮你建**，见下文。

文件改好后一般无需重启即可生效；如果是刚新建了整个 skills 文件夹，可在对话里输入 `/reload-skills`。

## SKILL.md 长什么样

文件分两部分：顶部用 `---` 包起来的"名片"（官方叫 frontmatter），下面是正文指令。

最重要的一项是 `description`：写清楚"这个技能做什么、什么时候该用"，Claude 就是靠它判断要不要启用。

常用的名片字段：

| 字段 | 作用 |
|---|---|
| `name` | 技能名，也是手动调用的命令名；不写则用文件夹名 |
| `description` | 做什么、何时用（强烈建议填写，把最主要的用途写在最前面） |
| `argument-hint` | 输入命令时的提示，如 `[公司名]` |
| `disable-model-invocation: true` | 只允许你手动调用，Claude 不会自己启用；有"对外发送"等副作用时建议开 |
| `allowed-tools` | 本技能运行期间免确认的工具，新手一般不用设 |

## 业务示例：调研报告生成

假设你在虚构的"启航贸易有限公司"做客户背景调研，希望每份调研都有统一结构。创建文件 `~/.claude/skills/research-report/SKILL.md`：

```text
---
name: research-report
description: 根据资料文件夹生成统一格式的公司调研报告。当用户要求"做调研报告""整理某公司背景"或提供一批公司资料时使用。
argument-hint: [公司名称]
---

# 调研报告生成

## 工作步骤
1. 读取当前文件夹中与【$ARGUMENTS】有关的全部资料，列出你读了哪些文件。
2. 按下面的结构写报告，保存为 reports/【公司名】-调研报告.md。
3. 每个结论后面注明来源文件名；找不到依据的内容写"资料中未提及"，不要推测。
4. 最后单独列出"待核实问题"清单。

## 报告结构
- 一、一句话概况（不超过 50 字）
- 二、公司基本信息（成立时间、规模、主营业务）
- 三、产品与客户
- 四、近期动态
- 五、合作切入点（给出 3 条，说明理由）
- 六、待核实问题

## 写作要求
- 中文，语言平实，不用夸张形容词。
- 数据必须带来源；不确定的写"待核实"。
```

注意正文里的 `$ARGUMENTS` 会被替换成你输入命令时写的内容。保存后：

- **手动调用**：在对话框输入 `/research-report 星河电子`。
- **自动调用**：你说"帮我整理星河电子的背景"，Claude 会根据 `description` 判断是否启用。

这里的"星河电子"和"启航贸易"都是虚构公司。

### 让 Claude 帮你写技能

不用从零写。直接对 Claude 说：

```text
请帮我在个人技能目录创建一个名为【research-report】的技能。
用途：【根据资料文件夹生成统一格式的公司调研报告】。
报告结构：【概况、基本信息、产品与客户、近期动态、合作切入点、待核实问题】。
要求：【每个结论标注来源，找不到依据就写"资料中未提及"】。
写好后给我看内容，再保存。
```

## 管理与检查技能

| 命令 | 作用 |
|---|---|
| `/skills` | 列出当前可用的技能 |
| `/skill-doctor` | 技能"体检"：每个技能占多少上下文、用得多不多、哪些从没用过，并建议关掉哪些（需 v2.1.252 及以上） |
| `/reload-skills` | 重新加载新建的技能文件夹 |

**为什么要体检？** 每个可被自动调用的技能，其名称和简介会常驻在 Claude 的"工作记忆"里。技能越多、简介越长，留给正事的空间越少。定期运行 `/skill-doctor`，把长期不用的关掉或删除，把简介写得更精炼。

优化技能的三个要点：

1. `description` 要具体：写"什么场景用"，不要只写"调研"两个字。
2. 正文短而清楚；官方建议 `SKILL.md` 不超过 500 行，参考资料放到同文件夹的其他文件里，在正文里点名引用。
3. 用真实任务试几次，哪里跑偏就改哪里，再试。

## 插件：打包分享技能的方式

如果你有一批技能想分享给同事，或想用别人做好的技能，就用**插件（Plugin）**。插件是一个"安装包"，可以同时带上技能、子代理、MCP 连接等。

- 在 Claude Code 里输入 `/plugin` 可以浏览和安装。
- 装上后，插件里的技能以"插件名:技能名"的形式出现，如 `/插件名:技能名`。
- 安全提醒：插件会以**你的权限**运行，只安装来源可信的插件（权限概念见[权限与安全](/advanced/permissions)）。

插件的安装来源、判断方法和自己打包，放在选学专题，见[插件与 Mods](/advanced/optional/plugins-mods)。

## 课堂练习

1. 挑一项你每周都要重复做的工作（周报、调研、回复），先写下 3–5 个步骤和输出格式。
2. 用上面的"让 Claude 帮你写技能"提示词，生成对应技能。
3. 准备 2–3 份虚构公司资料放进文件夹，输入 `/技能名 公司名` 运行一次，对照结果修改 `SKILL.md`。
4. 运行 `/skills` 和 `/skill-doctor`，看看你的技能占多少上下文。

## 小结

- 技能是一份"做事手册"，用到时才读全文，适合固化重复流程。
- 一个技能 = 一个文件夹 + `SKILL.md`；`description` 决定 Claude 何时启用。
- `/skill-doctor` 定期体检，插件用于打包分享。
