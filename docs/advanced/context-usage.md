# 上下文与用量管理

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 解释"上下文"是什么，为什么对话太长会"忘事"、变慢、更费额度
- 在压缩、清空、回退、新开几种做法中选对一种
- 用 `/context` 和 `/usage` 查看占用与用量
- 养成几个省用量的习惯

## 一、上下文：AI 的"工作台"

Claude 并不是"记得"整个对话，而是每次回答前，把**当前对话里的所有内容一起重新读一遍**。这些内容占用的空间就叫**上下文**，容纳它们的地方叫**上下文窗口**。你可以把它想成一张桌子：

- 桌子的大小有限（窗口大小）
- 你说过的话、它读过的文件、它的回答、工具的输出，都摊在桌上
- 桌子摆满了，就得收拾——旧的东西要被浓缩或移走

在 Claude Code 里，桌上的东西比你想象的多。开始工作之前，就已经有：系统指令、你的 CLAUDE.md、自动记忆、可用工具的名字清单等。之后它每读一个文件，整个文件内容都会摊上桌；你要它处理 30 份访谈记录，这 30 份内容很可能都在桌上。

这就是 [AI 的能力与局限](/guide/limits) 里说过的"工作记忆有限"在 Claude Code 里的具体表现。

### 为什么长对话会出问题

1. **会"忘事"或"乱"**：桌面太满，早期的要求容易被淹没或被压缩时丢失细节
2. **变慢**：每次回答都要重新读全部内容
3. **更费额度**：官方说明，Claude Code 每次请求都会带上完整的对话；即使你只问一句话，如果这个对话已经开了一整天，也要为整个对话的"重读"计入用量

## 二、对话变长时的四种办法

| 办法 | 做什么 | 什么时候用 | 代价 |
|---|---|---|---|
| **压缩** `/compact` | 把前面的对话总结成摘要，继续同一个对话 | 同一件事做到一半，还要接着做 | 细节会被概括，可能丢失 |
| **清空** `/clear` | 开始全新对话，上下文清零（CLAUDE.md 和记忆仍会读入） | 换成了不相关的新任务 | 之前的对话不再在桌上，但可用 `/resume` 找回 |
| **回退** `/rewind` | 回到之前某个时间点，也可以只"从这里开始压缩" | 中途走偏了，想回到走偏前 | 之后的内容被丢弃 |
| **新开** | 开一个新的对话窗口，并行处理另一件事 | 两件事互不相关、都要继续 | 需要自己管理多个对话 |

### 压缩 `/compact`

```text
/compact 保留所有已确认的结论、每份文件的编号对应关系，以及我提出的写作要求；丢弃中间的讨论过程
```

`/compact` 后面可以写**压缩说明**，告诉它摘要时重点保留什么。这是整页最值得学的技巧之一：不写说明的时候，它会按自己的判断概括。

官方说明的"压缩之后还在的东西"：

| 内容 | 压缩后 |
|---|---|
| 系统指令 | 保留 |
| 项目根目录的 CLAUDE.md、自动记忆 | 重新从磁盘读入，不会丢 |
| Plan 模式写的方案 | 重新读入 |
| 读过或改过的文件 | 最多重新读最近改动的 5 个，较大的文件只留路径 |
| 你调用过的技能 | 重新带入，但有长度上限，超出的旧技能会被丢 |
| 子文件夹里的 CLAUDE.md、带路径限定的规则 | 和对话一起被概括，用到时再触发加载 |
| **你和 Claude 之间的具体对话细节** | **被摘要替代，细节会丢** |

你还可以在 CLAUDE.md 里提前写好"压缩时要保留什么"：

```markdown
# 压缩说明
压缩对话时，请保留：已确认的结论、文件清单和每份文件的处理状态、我提的格式要求。
```

### 自动压缩

不用每次手动。Claude Code 在接近上限时会**自动压缩**，所以窗口满了也不会让对话报废。需要更早压缩时，可以用 `/autocompact` 设置阈值，例如 `/autocompact 500k`；输入 `/autocompact auto` 则恢复为按模型调好的默认值。

新版本还加入了对闲置长对话的自动压缩，具体触发条件以官方为准。

### 清空 `/clear`

最简单有效：**换任务就清空**。官方提示，不相关的旧上下文会在之后每条消息里白白占用额度。清空之前可以先用 `/rename` 给当前对话起个名字，之后用 `/resume` 找回来。

### 回退里的"压缩"

在回退菜单（`/rewind` 或输入框为空时双击 `Esc`）里，选一条历史消息，可以选择：

- **Summarize from here**：把这条之后的内容压缩，保留前面的原样
- **Summarize up to here**：把这条之前的内容压缩，保留后面的原样

适合"开头的指令很重要，中间一大段试错过程可以浓缩"。选中后，可以在 add context 一栏写摘要的重点要求。不改磁盘上的文件。

### 更大的窗口

部分新模型支持约 100 万 token（词元）的上下文窗口，意味着一次能摆下更多资料，压缩的工作方式不变。窗口大小与模型、套餐有关，详见 [3.8 模型选择与推理强度](/advanced/models)。窗口大不等于可以不管理，对话越长，仍然越慢越费额度。

## 三、用 `/context` 看一眼桌面

输入 `/context`，会用彩色格子显示上下文的占用情况，并给出优化建议，例如哪些工具或文件占用太大、记忆文件是否过长、是否快满了。感觉它"变笨了"或"变慢了"时，先看一眼。

在终端版里输入 `/context all` 可展开详细列表。

## 四、用量：看得见才管得住

### 查看用量

输入 `/usage`（`/cost` 是它的别名）：

- **订阅用户**：会看到各个限额窗口的使用进度条、重置时间，以及"是什么在消耗你的额度"的拆解：按技能、子代理、插件、MCP 服务各占多少，并提示"长上下文""缓存失效"等行为占比
- **使用 API 或第三方云平台的用户**：显示本次会话的花费估算和各模型 token 数
- 在 VS Code 里，`/usage` 会打开"账户与用量"窗口，可切换"日 / 周"视图；需 v2.1.277 及以上时，非订阅登录方式也能看到本次会话的用量

注意：这些数字是**根据你本机的会话记录估算**的，不含你在其他设备或网页上的使用，仅供参考，准确的账单信息以官方后台为准。具体套餐额度和价格，请看 [Anthropic 官方定价页](https://claude.com/pricing)，本教程不列具体数字。

### 用完额度怎么办

订阅套餐的额度按时间窗口计量（例如若干小时的窗口和周窗口），到上限时界面会提示什么时候重置。可选做法：

- 等待重置
- 如果你的账号开通了"额外用量"，可用 `/usage-credits` 查看和管理
- 需 v2.1.234 及以上时，Claude Code 可以在额度重置后自动接续被中断的任务

### 省用量的习惯

按效果从高到低：

1. **换任务就 `/clear`**，不要让一个对话开一整天
2. **提示词具体**。"整理这份访谈"比"看看这个文件夹有什么"读的文件少得多；"优化一下"这种模糊请求会触发大范围阅读
3. **大任务先 Plan**，避免做错重来
4. **选对模型**。简单、批量、重复的小任务用较轻的模型（如 Claude Haiku 5.5 或 Claude Sonnet 5.5），复杂推理再用 Claude Opus 5.5 或 Claude Fable 5.1。详见 [3.8](/advanced/models)
5. **降低推理强度**。简单任务用 `/effort` 调低，想得越深越慢越费
6. **关掉不用的外部连接**。每个 MCP 服务都会增加桌面上的东西，用 `/mcp` 检查并关闭不用的（见 [3.10](/advanced/mcp)）
7. **把"只在特定流程才需要"的长说明，从 CLAUDE.md 移到技能里**，技能是用到才加载（见 [3.9](/advanced/skills)）。CLAUDE.md 建议控制在 200 行以内
8. **把"又长又杂"的读取交给子代理**，让它读完只带回摘要（见 [3.11](/advanced/agents)）
9. **别开太多并行任务**。每个子代理、每个定时任务、每个并行会话都有自己的上下文和用量

其中有几项会让你"悄悄"耗用量，容易忽视：长时间不关的老对话、一直在跑的定时任务、很多会话互相传话、没用的外部连接。

## 五、一个对比：同样的任务，两种做法

任务：处理 20 份调研文档，输出汇总表和一份报告。

| 做法 | 过程 | 结果 |
|---|---|---|
| 差 | 在一个对话里，先汇总，接着写报告，再顺手问五个无关问题，挂一整天 | 上下文被汇总过程的细节塞满，报告中前后矛盾，用量高 |
| 好 | ① Plan 出方案 ② 汇总完成后 `/compact` 并写明保留要点 ③ 写报告 ④ 报告定稿后 `/clear` 再问别的事 | 每个阶段上下文清爽，结果稳定，用量少 |

## 动手任务

1. 在练习文件夹里让 Claude 读完所有文件并写一份概要，输入 `/context` 查看占用
2. 用 `/compact` 加上"保留文件清单和结论，丢弃过程"的说明进行压缩，再 `/context` 对比
3. 输入 `/usage`，找出当前会话占用最多的部分
4. 给当前对话 `/rename`，再 `/clear`，最后用 `/resume` 找回

## 小结

- 上下文是 AI 的工作台，越满越慢、越容易乱、越费额度
- 四种办法：压缩（接着做）、清空（换任务）、回退（走偏了）、新开（并行）
- `/compact` 后面写上"保留什么"，效果显著不同
- `/context` 看占用，`/usage` 看用量；换任务就 `/clear` 是最划算的习惯
