# 子代理与 Agent 循环

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 说清子代理是什么，为什么它能让大任务更快、对话更干净
- 让多个子代理并行做调研，并知道后台运行是什么意思
- 用 `/loop` 让 Claude 定期重复检查某件事
- 创建一个自己的子代理（如"资料核对员"）

## 子代理是什么

**子代理（Subagent）是 Claude 派出去干活的"助手"。** 每个子代理有自己独立的"工作记忆"，干完活只把**结论**交回来。

打个比方：你是项目经理，要调研 5 家公司。自己一家家读，资料会把你的脑子塞满；不如派 5 个助手各查一家，只让他们交 5 份摘要。这样：

- **更快**：多个助手可以同时做。
- **主对话更干净**：几十页原始资料留在助手那里，不占你的上下文（上下文的概念见[上下文与用量管理](/advanced/context-usage)）。
- **可分工**：每个助手可以限定只能做什么。

要注意：子代理的用量**照样计入你的额度**，多个并行意味着消耗更快，所以大任务才值得拆。

## 内置的助手

Claude Code 自带几类子代理，你不用配置，Claude 会在需要时自己派：

| 名称 | 用途 |
|---|---|
| Explore | 只读地快速查找、分析资料，不会修改文件 |
| Plan | 在 Plan 模式下做调研，为方案收集信息 |
| general-purpose | 通用助手，能处理需要多步查找加动手的任务 |

## 并行调研示例

对 Claude 说：

```text
请并行调研下面【3】家公司，每家派一个子代理：
【星河电子、远帆家居、青禾食品】（均为虚构公司）
资料在 companies/ 文件夹里，每家一个子文件夹。

每个子代理需要：
1. 读完该公司文件夹里的全部资料；
2. 按 research-report 技能的结构，写出 500 字以内摘要；
3. 单独列出资料中互相矛盾或缺失的信息。

全部完成后，你再汇总成一张对比表，保存到 reports/对比表.md。
```

要点：

- 明确"每个对象一个子代理"，Claude 就会并行去做。
- 要求"只交摘要"，避免原始资料灌回主对话。
- 汇总由主对话负责，你只需要审阅最后的对比表。
- 也可以让技能配合：见[Skills](/advanced/skills)。

### 后台运行

**后台运行**指助手在你看不见的地方继续干，你可以接着和 Claude 聊别的事，完成后会收到通知。

- 子代理默认可在后台运行（该行为自 2026 年 7 月起为默认）。
- 前台运行的助手会"占住"主对话，直到它做完；后台运行则不会。
- 对运行中的任务，可按 `Ctrl + B` 把它转到后台。
- 后台助手需要你确认的操作，会在主对话里弹出，并标明是哪个助手发起的。

### 分叉：让助手带着当前上下文去做

有时你希望助手"已经了解刚才聊的所有背景"，可以用**分叉（fork）**：它继承完整对话，但它的过程不占主对话。在 v2.1.212 及以上，输入 `/subtask 【任务描述】` 启动；v2.1.161 至 v2.1.211 版本中对应的命令是 `/fork`。

### 数量与层级

默认最多同时 20 个子代理运行；子代理还可以再派子代理，默认最多三层。新手不需要改这些设置，了解即可。

## 用 /loop 循环处理

前面是"一次任务拆给多人"，`/loop` 是"同一件事隔段时间再做一次"。输入格式：

```text
/loop 【间隔】 【要做的事】
```

例子：

```text
/loop 30m 检查 inbox/ 文件夹里有没有新增的客户来信，有就按 research-report 技能整理要点，追加到 reports/来信汇总.md
```

间隔支持秒（`s`）、分（`m`）、时（`h`）、天（`d`），最小一分钟。三种用法：

| 写法 | 效果 |
|---|---|
| `/loop 5m 检查……` | 每 5 分钟固定执行 |
| `/loop 检查……`（不写间隔） | 由 Claude 根据情况自己决定隔多久 |
| `/loop` | 执行内置的"收尾维护"提示词，或你自己写在 `.claude/loop.md` 里的默认任务 |

必须知道的限制：

- **只在 Claude Code 开着时才运行。** 关闭窗口或退出，循环就停了；电脑休眠也不执行。
- **7 天后自动失效**，到期前会最后执行一次。
- 每次执行前都会按权限规则请你确认，除非你已设置自动批准（见[权限与安全](/advanced/permissions)）。
- 循环会持续消耗用量，不用了请及时停止：自定节奏的循环按 `Esc` 停；也可以直接对 Claude 说"取消刚才的定时检查"。

要电脑关机也能运行的定时任务（云端例行任务）、让 Claude 一直做到目标完成的 `/goal`，见[目标与定时](/advanced/optional/goal-schedule)。几十上百个子代理的大规模调研，见[动态工作流](/advanced/optional/workflows)。

## 自定义子代理

当某类助手反复出现，就把它固定下来。子代理是一个 Markdown 文件，放在：

| 位置 | 谁能用 |
|---|---|
| `.claude/agents/` | 当前工作文件夹（项目） |
| `~/.claude/agents/` | 你的所有项目 |

示例，文件 `~/.claude/agents/fact-checker.md`：

```text
---
name: fact-checker
description: 资料核对员。检查报告里的数据和结论是否能在原始资料中找到依据。写完报告后、对外发出前使用。
tools: Read, Grep, Glob
model: sonnet
---

你是严谨的资料核对员。
对给你的报告逐条检查：
1. 每个数据、日期、名称，是否能在原始资料中找到出处；
2. 找不到出处或与资料不一致的，列出原文位置和差异；
3. 只报告问题，不要改动任何文件。
输出：问题清单，按严重程度排序。
```

字段说明：`name` 和 `description` 必填，`description` 决定 Claude 何时派它；`tools` 限定它只能做哪些事（这里只读，不能改文件）；`model` 指定模型（见[模型选择](/advanced/models)），核对类工作用 `sonnet` 通常够用。

怎么用：

- 对话里直接说"让 fact-checker 检查 reports/对比表.md"；
- 或输入 `@` 后选择它，这样保证一定是它来做。

最简单的创建办法同样是让 Claude 代劳：

```text
请帮我创建一个子代理【fact-checker】，放在个人目录下。
职责：【检查报告里的数据是否能在原始资料中找到依据】。
限制：【只能读文件，不能修改】。
```

## 业务场景速览

| 类型 | 用法 |
|---|---|
| 调研 | 每家公司一个子代理并行读资料，主对话汇总对比 |
| 分析 | 一个子代理清洗数据，另一个出结论，第三个核对 |
| 提效 | `/loop` 定期整理新资料、更新汇总表 |
| 质检 | 自定义"核对员"，每份报告交付前过一遍 |

## 课堂练习

1. 准备 3 个虚构公司的资料子文件夹（每个放 1–2 份简短文字），用并行调研提示词跑一次，观察是否同时开始。
2. 创建 `fact-checker` 子代理，让它检查刚生成的对比表，看它能否找出你故意埋入的一处错误数据。
3. 用 `/loop 5m` 让 Claude 每 5 分钟报告 `inbox/` 里的文件数量；往里放一个新文件，观察变化；练习结束后停止循环。

## 小结

- 子代理是独立工作记忆的助手，只交结论，适合并行调研和分工。
- 后台运行让你不被占住；`/loop` 让同一件事定期重复，只在会话开着时有效。
- 反复出现的角色可以写成自定义子代理，限定工具和模型。
