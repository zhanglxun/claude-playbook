# 研发行业

> **预留，内容后续补充。** 本页只说明计划涵盖的方向，不是完整教程。

研发团队的日常是读资料、写文档、查问题、做评审。这些工作文字量大、格式固定，适合与 Claude 配合。后续补充时，同样遵循"分析框架、示范提示词、课堂练习、两种做法对照"的结构，案例使用虚构项目。

## 计划涵盖的高频场景方向

1. **技术文档整理与改写**：把零散的设计笔记整理成规范文档，或把专业文档改写成面向业务人员的说明。
2. **需求梳理与评审准备**：从会议记录、邮件中提取需求清单，列出待澄清的问题和风险。
3. **测试用例与检查清单起草**：根据需求描述起草测试点，由人审核补充。
4. **问题复盘与周报**：把工作记录整理成结构化的复盘和周报。
5. **文献与标准资料速读**：对公开技术资料做摘要和要点对照，标注出处供人核对。

## 使用前提醒

- 未公开的源代码、设计图纸、技术秘密不要上传，先按 [使用规范与数据安全](/security/) 判断。
- 技术结论由专业人员验证，Claude 的输出只作草稿。
