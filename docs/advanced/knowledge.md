# 让业务产生持续的数据沉淀

> 内容核对日期：2026-10-18；涉及的功能以 Claude Code 当时版本为准，请以官方文档为准。

## 学完这页你能…

- 理解为什么"每次产出都留在对话里"等于白做
- 设计一个让 Claude 能持续读、持续写的文件夹结构
- 用模板、CLAUDE.md、技能把产出格式固定下来
- 用自动化让资料库自己"长大"，并保持可核查

## 问题：对话结束，成果就散了

每次对话结束，Claude 会"忘掉"这次聊过的内容（原理见[上下文与用量管理](/advanced/context-usage)）。如果调研结果只留在聊天窗口，下个月再查同一个客户，一切从头来。

解决办法的核心思路是：**让产出变成文件，文件放进有规矩的文件夹，让规矩写进说明书。** 这样今天的产出，就是明天的资料。

三个层次：

| 层次 | 做法 | 作用 |
|---|---|---|
| 存放 | 文件夹结构 + 命名规则 | 东西放哪、叫什么，大家一致 |
| 规范 | 模板 + CLAUDE.md + 技能 | 产出格式固定，Claude 自动照做 |
| 积累 | 汇总数据表 + 自动化 | 每份新产出自动进入总表 |

## 示例：客户调研资料库

下面用虚构公司"启航贸易有限公司"的业务团队演示（仅为示例，非真实客户）。

```text
客户调研资料库/
├─ CLAUDE.md                 说明书：本库的规则（见下文）
├─ README.md                 给人看的使用说明
├─ _templates/               模板区
│  ├─ 调研报告模板.md
│  ├─ 沟通记录模板.md
│  └─ 汇总字段说明.md
├─ 01-原始资料/              只放原始资料，不改动
│  ├─ 星河电子/
│  │  ├─ 2026-09-官网介绍.pdf
│  │  └─ 2026-09-展会名片整理.md
│  └─ 远帆家居/
├─ 02-调研报告/              Claude 生成的报告
│  ├─ 星河电子-调研报告-2026-09.md
│  └─ 远帆家居-调研报告-2026-09.md
├─ 03-沟通记录/              每次沟通一条
│  └─ 2026-09-15-星河电子-线上会议.md
├─ 04-汇总表/                积累下来的数据表
│  ├─ 客户总表.csv
│  └─ 待办跟进.csv
└─ .claude/
   ├─ skills/
   │  └─ research-report/SKILL.md
   └─ agents/
      └─ fact-checker.md
```

设计原则：

1. **原始资料与成果分开**：`01-原始资料` 只增不改，出了问题随时能回头对照原文。
2. **编号前缀固定顺序**：文件夹按流程排列，一眼看懂。
3. **文件名带"公司名+日期"**：既好找，也方便 Claude 判断新旧。
4. **汇总表用 CSV 或 Markdown 表格**：纯文本，Excel 可直接打开，Claude 读写最稳。
5. **隐藏的 `.claude` 文件夹放技能和子代理**：跟着资料库走，换电脑或交接时一起带走。

> 提醒：真实客户资料属于敏感信息，放入前先对照[使用规范与数据安全](/security/)。公开分享的案例一律使用虚构公司。

## 模板：让每份产出长得一样

模板是"填空题"。例如 `_templates/沟通记录模板.md`：

```text
# 【公司名】沟通记录

- 日期：【YYYY-MM-DD】
- 参与人：【我方 / 对方】
- 沟通方式：【线上会议 / 电话 / 邮件】

## 对方关注点
-

## 我方承诺事项
-

## 待办（负责人、截止日期）
-

## 下一步计划
-
```

模板的价值：Claude 按它生成，格式永远一致；一致的格式，才能被汇总成数据表。

## CLAUDE.md：给资料库立规矩

在资料库根目录放一份 `CLAUDE.md`，Claude 每次打开这个文件夹都会先读它（写法见 [CLAUDE.md](/advanced/claude-md)）。示例：

```text
# 客户调研资料库

## 目录规则
- 01-原始资料：只读，不得修改或删除其中任何文件。
- 新报告保存到 02-调研报告，文件名：【公司名】-调研报告-【YYYY-MM】.md。
- 新沟通记录保存到 03-沟通记录，文件名：【YYYY-MM-DD】-【公司名】-【方式】.md。

## 写作规则
- 报告必须使用 _templates/调研报告模板.md 的结构。
- 每个事实标注来源文件名；资料里没有的写"资料中未提及"，不得推测。
- 所有金额、数量保留原文单位。

## 沉淀规则
- 每生成一份调研报告或沟通记录，必须同步更新 04-汇总表/客户总表.csv 对应行。
- 待办事项同步追加到 04-汇总表/待办跟进.csv。
- 更新汇总表前先告诉我将改动哪几行。
```

另外，Claude Code 有"自动记忆"功能，会自己记下你的纠正和偏好；可输入 `/memory` 查看或开关。但**业务规则请写在 CLAUDE.md 里**，因为你能直接看到、修改，也能和同事共享。

## 让汇总表自己长大

有了模板和规矩，就可以把"新资料进来 → 生成成果 → 进入总表"做成固定动作：

**方式一：一句话触发。**

```text
我刚把【远帆家居】的资料放进了 01-原始资料/远帆家居/。
请：
1. 用 research-report 技能生成调研报告，保存到 02-调研报告；
2. 把关键字段追加到 04-汇总表/客户总表.csv；
3. 让 fact-checker 检查报告，把问题清单告诉我。
```

**方式二：用 `/loop` 定期巡检。**

```text
/loop 1h 检查 01-原始资料/ 里有没有尚未生成调研报告的新公司，有就按规则处理并更新汇总表，处理完告诉我做了什么
```

`/loop` 只在会话开着时运行，且 7 天后失效（详见[子代理与 Agent 循环](/advanced/agents)）。要电脑关机后仍定期运行，见[目标与定时](/advanced/optional/goal-schedule)。

**方式三：用 Hooks 自动检查。** 例如每次改动汇总表后自动校验格式，属于选学内容，见 [Hooks](/advanced/optional/hooks)。

### 汇总表字段示例

`04-汇总表/客户总表.csv` 的表头可以这样定：

| 公司名 | 行业 | 主营产品 | 调研日期 | 报告文件 | 合作切入点 | 状态 |
|---|---|---|---|---|---|---|
| 星河电子 | 电子 | 智能家居配件 | 2026-09 | 02-调研报告/星河电子-调研报告-2026-09.md | 样品试用 | 待跟进 |

字段在 `_templates/汇总字段说明.md` 里写清楚，Claude 才不会今天加一列、明天改一列。

## 保持资料库可信

- **抽查来源**：定期随机选一条结论，回到原始资料核对。
- **版本留存**：重要文件修改前先复制备份，或使用文件夹的云盘历史版本。
- **敏感信息分级**：含联系方式、报价的文件单独放，不放进共享给更多人的目录。
- **定期整理**：每月让 Claude 列出"超过 90 天未更新的客户"，由你决定是否更新或归档。

## 课堂练习

1. 在桌面新建"客户调研资料库"，按上面的结构建好文件夹（可让 Claude 代劳：描述结构，让它创建）。
2. 让 Claude 帮你写好 `CLAUDE.md` 和两个模板，你审阅并修改。
3. 放入 2 家虚构公司的资料，运行"方式一"的提示词，检查报告和总表是否一致。
4. 用文字写出你自己业务中"每次产出都该进入哪张表"，列出表头。

## 小结

- 把产出变成文件，把规矩写进 CLAUDE.md，把格式固定成模板，资料才能越积越多。
- 原始资料与成果分开，汇总表用纯文本，字段先定义清楚。
- 自动化可以让总表自己更新，但要保持抽查和核对。
