# 动态工作流（Workflows）

> 内容核对日期：2026-10-18；选学内容。部分功能为研究预览/公测，且按套餐和版本开放，请以官方文档为准。

**适合谁**：要做大批量调研、资料交叉核对的业务人员。

**学完这页你能**：说清"动态工作流"和子代理的区别；用 `/deep-research` 跑一次深度研究；让 Claude 为你的任务写一份编排脚本，用 `/workflows` 看进度，并把好用的流程保存下来复用；知道它很费用量，如何先小范围试跑。

## 它是什么

回忆 3.11：子代理是 Claude 临时派出的"助手"，一轮派几个。但如果任务是"把 200 份供应商资料逐份读完、再互相核对"，让 Claude 一轮一轮地调度，既慢又容易乱。

**动态工作流**换了个思路：由 Claude 先写一份"编排脚本"（一份用代码写的调度计划），再由程序在后台按脚本调度**几十到上百个**子代理干活，中间结果都留在脚本里，最后只把结论交给你。过程中你可以继续聊别的。

它还能内置"质量套路"，例如让独立的代理互相挑对方结论的毛病，再汇报，结果比一遍过更可信。

> 你不需要自己写脚本，Claude 会写。你只需要看懂计划、批准运行。

## 和子代理、技能、agent teams 的区别

| | 子代理 | 技能（Skills） | Agent teams | 工作流 |
|---|---|---|---|---|
| 是什么 | Claude 派出的一个助手 | Claude 照着做的一份说明 | 一个主管带多个并行会话 | 由程序执行的一份脚本 |
| 谁决定下一步 | Claude，逐轮决定 | Claude，照说明 | 主管代理，逐轮决定 | 脚本 |
| 中间结果在哪 | Claude 的对话里 | Claude 的对话里 | 共享任务清单 | 脚本变量里 |
| 规模 | 一轮几个 | 同子代理 | 少数几个长期同伴 | 一次几十到上百个 |

一句话：**计划交给脚本，就是工作流**。

## 方式一：用内置的 /deep-research

Claude Code 自带一个工作流叫 `/deep-research`：围绕一个问题，从多个角度联网搜索，读取并交叉核对来源，对每条结论"投票"，最后给出带出处的报告，没通过核对的说法会被剔除。需要联网搜索工具可用。

在 Claude Code 对话框里输入：

```text
/deep-research 【你要研究的问题，如：东南亚三国近三年对家用小家电的进口认证要求有何变化】
```

Claude Code 会询问是否允许运行工作流，选 **Yes**。随后任务进入后台，你可以输入 `/workflows` 查看进度：能看到分了几个阶段、各有多少代理、每个代理查到了什么。核验不了的结论会标为"未验证"，而不是当作错误。

## 方式二：让 Claude 为你的任务写一个工作流

两种触发办法：

- 在提问里直接说"用一个工作流来做……"。
- 提问里带上关键词 `ultracode`，Claude 就会为这件事写工作流，而不是一轮一轮地做。

```text
ultracode：把 research/suppliers/ 下每份供应商资料逐份提取【资质、交期、起订量】，
再让独立代理交叉核对相互矛盾的地方，最后汇总成一张对比表。
```

另有 `/effort ultracode` 可让整个会话里的每个较大任务都自动用工作流，**用量会明显增加**，一般不建议新手打开。

运行前 Claude Code 会展示计划的阶段并询问是否运行；选 **View raw script** 可以先看脚本。工作流里的代理做事同样受你的权限设置约束。

### 看进度与控制

输入 `/workflows` 打开进度界面（需在 Claude Code 里输入）。常用按键：方向键选阶段、Enter 看详情、`p` 暂停或继续、`x` 停止、`s` 保存。

## 保存并复用

某次运行结果满意，就在 `/workflows` 里选中它按 `s` 保存。可存到：

- 项目的 `.claude/workflows/`：随项目共享给同事
- 个人的 `~/.claude/workflows/`：所有项目可用，只有你自己能看到

保存后就是一条你自己的命令 `/名称`，下次直接用，而且每次执行同样的调度流程，适合每月例行的调研核对。

## 成本与注意事项

- 工作流会派出大量代理，**一次运行可能比平常对话多耗很多用量**，计入套餐的用量和速率限制；具体额度请看[官方说明](https://code.claude.com/docs/en/workflows)和你账号的用量页面。
- 规模较大（代理数多或预计消耗高）时，任务栏会出现 `Large workflow` 提示，可到 `/workflows` 里随时停止。
- 建议先拿**一小部分**试跑：先处理一个文件夹、一个窄问题，确认方向再放大。
- 跑之前用 `/model` 看一下当前模型，批量任务可让 Claude 在不需要最强的环节改用较小的模型（如 Claude Sonnet 5.5 或 Claude Haiku 5.5）。
- 可用性：官方文档写明动态工作流面向付费套餐；Pro 套餐需要在 `/config` 中手动打开。组织管理员可能关闭该功能。
- 部分更新依赖版本，例如运行遇到用量上限时自动等待重置需要 Claude Code v2.1.271 或更高版本。

## 动手任务

1. 选一个你熟悉的小问题，运行一次 `/deep-research`，用 `/workflows` 观察各阶段。
2. 核对报告里 3 条结论的出处链接是否真的支持原话。
3. 进阶：在一个只有 5 到 10 份资料的小文件夹上，用 `ultracode` 让 Claude 写一个"逐份提取并汇总"的工作流，满意后保存为自己的命令。

## 小结

- 工作流 = 脚本调度大量子代理，适合大批量、需交叉核对的任务。
- `/deep-research` 是现成的入口；`ultracode` 或"用工作流做"可以定制。
- 先小范围试跑，注意用量。
